# JMQX 企业级建设路线图

## 1. 目标与分层

本路线图用于将 JMQX 从“功能可用”升级为“企业可生产运行”，按三层推进：

- **P0（可上线）**：稳定性与可运维性达到生产最低标准。
- **P1（规模化）**：支撑更大连接规模与更复杂业务场景。
- **P2（企业能力）**：多租户、安全合规、生态集成与商业化能力完善。

---

## 2. P0（可上线）能力清单

### 2.1 稳定性与可靠性

- 完整链路压测基线：CONNECT / SUBSCRIBE / PUBLISH / DISCONNECT。
- 关键路径超时与熔断：鉴权插件、桥接插件、集群 RPC。
- 异常隔离：慢订阅者剔除、桥接失败降级、局部组件失败不拖垮主链路。
- 内存与磁盘保护：遗嘱、保留消息、QoS 持久化的容量阈值与淘汰策略。

### 2.2 运维与可观测

- 指标体系：连接数、订阅数、入/出消息速率、延迟分位、失败率、堆外内存、文件句柄。
- 结构化日志：连接日志、协议日志、鉴权日志、桥接日志、集群复制日志统一字段。
- 健康探针：`readiness/liveness` + 关键依赖自检。
- 运维命令集：在线查看会话、强制踢线、流控开关、热点 topic 诊断。

### 2.3 工程质量

- CI 门禁：编译、单测、集成测试、静态检查、依赖漏洞扫描。
- 回归用例：MQTT 3.x/5.0 协议兼容、QoS 0/1/2、共享订阅、遗嘱、保留消息。
- 配置治理：按模块拆分 YAML + 字段注释 + 默认值与风险提示。

---

## 3. P1（规模化）能力清单

### 3.1 性能与容量

- 目标容量分级：
  - 单机稳定 30 万连接（第一里程碑）。
  - 单机冲刺 50 万连接（第二里程碑，按硬件配置评估）。
- 热路径优化：
  - 订阅/退订批处理与局部锁优化。
  - 发布路由减少无效查找（先全局后本地）。
  - I/O 线程与业务线程隔离，统一异步持久化队列。

### 3.2 集群能力

- Core/Replicant 架构闭环：选主、复制、重放、快照、节点下线清理。
- 跨节点一致性：订阅、会话、保留消息、QoS 状态在故障切换后可恢复。
- 动态扩缩容：节点加入/退出、流量迁移、连接重平衡策略。

### 3.3 管理能力

- 管理页面完善：集群概览、客户端视图、安全配置、动态参数变更。
- 配置热更新：ACL/Auth 链式插件动态启停与顺序调整（无重启）。
- 审计追踪：谁在何时修改了什么配置、变更前后对比与回滚。

## 4. P2（企业能力）清单

### 4.1 安全与合规

- 统一身份认证（SSO / OAuth2 / LDAP）接入。
- 细粒度 RBAC（菜单、API、租户、资源级权限）。
- 敏感数据治理：密钥托管、传输加密、存储加密、操作审计。

### 4.2 多租户与资源隔离

- 租户维度配额：连接数、主题数、消息吞吐、桥接带宽。
- 限流与优先级：按租户/客户端/IP 的策略组合。
- 噪声隔离：单租户异常负载不影响全局。

### 4.3 生态与交付

- 对接生态：Kafka / RocketMQ / MySQL / HTTP 回调增强（可观测、重试、幂等）。
- Helm 与容器化最佳实践：灰度发布、滚动升级、自动回滚。
- 企业交付物：SLA/SLO 文档、故障演练手册、容量评估模型、版本升级策略。

---

## 5. 里程碑建议（按季度）

- **Q1**：完成 P0（可上线）闭环，并形成标准化运维手册。
- **Q2**：完成 P1 核心能力（30 万稳定 + 集群核心闭环 + 管理面增强）。
- **Q3**：推进 P2（安全合规、多租户、生态集成）并开始试点客户落地。

---

## 6. 验收标准（建议）

- 稳定性：连续 7 天运行无严重故障，关键接口错误率低于设定阈值。
- 性能：在目标硬件下达到里程碑连接数与吞吐目标。
- 运维性：故障定位与恢复有标准流程，平均恢复时间（MTTR）可量化。
- 可演进：新增鉴权源、桥接目标、集群节点类型不需要大规模重构。
